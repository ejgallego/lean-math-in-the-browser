large decimal-output bottleneck. It does not reproduce every reported ratio.

qualification passes 37/40 cases, with three large-arithmetic timeouts.
That first campaign paused C/Emscripten preparation. The subsequent

## VIR phase attribution

A separate diagnostic run used the bundled `callTimed` API: one warmup and
three measured calls per case, checking every result hash outside the timer.
These instrumented phase medians are not headline benchmark samples.

| F(1,000,000) result | marshal | execute | decode | independently timed total |
|---|---:|---:|---:|---:|
| log2 (`fibBits`) | 0.042 ms | 425.903 ms | 0.050 ms | 426.076 ms |
| decimal (`fib`) | 0.051 ms | 423.970 ms | 23,942.916 ms | 24,368.395 ms |

The decimal-output cost is in result decoding. In the pinned SDK,
`liftObjectValue` sends a Nat to `readObjectDecimal`, which calls the Wasm
export `vir_obj_nat_decimal`. The shim uses `lean::mpz_value(value).to_string()`
for heap naturals before JS reads the text. The decode interval also includes
the boundary's other lifting work; it is not an isolated timer for that C++
method. The measurement nevertheless separates this cost from Lean function
execution directly. Host-import timing is zero in both cases.

The original Chrome/Worker, cold-start, CPU-throttling and frame-gap results
have not been rerun. Nor does this experiment establish a multiplication
algorithm diagnosis or justify assuming a universal interpreter overhead.

## Regular FIR preparation

The local `~/lean/fir` checkout is the requested `ejgallego/lean-fir` repository.
An isolated producer worktree is frozen at
`14be5c08bca91177fe033d13001a6bafeca22c19`, under
`.deps/fir-producer`. Its tracked files are unchanged. Build/source state is
local to that worktree, with FIR's prescribed toolchain-scoped artifact cache.

The scripts and templates are in [bench/backends](../bench/backends/README.md).
They stage the exact mathematical definitions, removing only the VIR metadata
import/export registrations, and record original and transformed source hashes.
No `.olean` or IR artifact is imported across toolchain versions.

The current version matrix is:

| component | Lean |
|---|---|
| original client/native/VIR | 4.34.0 |
| accepted FIR main used here | 4.34.0-rc2 |
| that producer's Emscripten runtime pin | 4.33.0 |

The direct `Tunnell.tunnell` root produces **25,441 bytes of zero-import Wasm**,
SHA-256 `853ee4d6228ea8b0d4c05c46ae6e6285560309be7f43b4917fc4a17b2148fa2e`.
The descriptor and actual Wasm import table both contain no imports. A fresh
instance for each n=1..400 agrees with VIR on all seven Verdict fields and with
the independent Python reference on counts and Boolean flags. The candidate,
captured LCNF, function inventory, build identity and check record live in
`.deps/fir-producer/.deps/math-browser-fir/_build/tunnell-direct.lufmIy/`.
This is a checked raw candidate, not a browser-qualified or immutable released
package. The subsequent Bench suite tests repeated calls through a diagnostic Node
adapter; browser behavior and a production adapter remain unqualified.

The initial preparation found these boundaries; the first now has a working
consumer capture route, and the second is outside the active scope:

1. **Bench module replay:** `primeCount` and `fibBits` both stop at
   `Failed to compile Bench.primeCount: Failed to find LCNF signature for Tunnell.isqrt`.
   The module-aware capture replays Bench declaration groups before the selected
   closure can be reduced. The direct Tunnell root succeeds, so this failure
   precedes runtime qualification of the wider workloads. Logs and exact build
   identities are retained under the `primeCount.*` and `fibBits.*` attempt
   directories. Investigate dependency-signature availability in postponed
   module replay before changing any mathematical code.
2. **Emscripten pin mismatch:** the frontend is 4.34.0-rc2 but the runtime recipe
   requires 4.33.0 commit `d8b18978322de05a8f3dba51ef03cf5461676c17`.
   The new preflight rejects this combination. The staged source and all-workload
   facade compile through the producer frontend to C, and the bridge passes
   `-std=c11 -Wall -Wextra -Werror` syntax checking. Wasm compilation/linking and
   execution remain untested pending a matching accepted frontend/runtime.

There is also an anticipated C-link dependency to resolve after the pin check:
the generated `Tunnell.c` and `Bench.c` call `initialize_Lean` and
`runtime_initialize_Lean` because the original modules publicly import Lean.
The generic builder links `libStd`, `libInit`, and `libleanrt`, not `libLean`.
The compiler/tactic import boundary or linked library closure therefore needs
an explicit decision; this has not yet been tested at the Emscripten linker.
No initializer stubs or import substitutions were introduced in this pass.

The Emscripten recipe selects the unthreaded profile for the existing Worker
application. Its upstream runtime setup currently uses `USE_GMP=OFF`, so this
backend is not automatically a test of adding GMP to the browser.

No FIR tracked source changed. Building ordinary `.olean` interfaces gives

needed for source-dependency discovery and compilation. With this route, all
ten original Bench entries emit zero-import resident modules (11,715–25,460
bytes). Definitions and module boundaries are unchanged. This is a different
supported capture API, not a fix to postponed module replay.

The full artifact/hash index is local at
`.deps/fir-producer/.deps/math-browser-fir/_build/suite-ordinary-unit.json`;
build identities alongside each artifact pin FIR `14be5c08b`, Lean rc2 commit
`6a10ac8c22beadecabdbb0919c2b50214762f91d`, emitter and source hashes.

`check-fir-suite.mjs` checks increasing/decreasing input sequences and immediate
repeats on retained instances. Each result is copied before cache-aware arena
rewind. Warm calls must return exactly to their prior checkpoint. A terminated
call discards its worker/instance before later cases. The bounded report
`suite-checks-bounded.json` records **37/40 qualified inputs, 148 successful
calls, no completed-result mismatches**, and these unqualified cases:

Both Fibonacci variants pass at 100,000 and take roughly 5–7 seconds in this

The diagnostic adapter depends on this producer’s concrete physical layouts;

## Balanced regular-FIR comparison

A separate campaign uses all six permutations of FIR/VIR/native order (six
measured values per engine/input). Every measured result passes its expected
hash. Selection is exploratory: the largest qualified input per workload whose
FIR screening samples were all under one second. Thus Fibonacci uses 10,000
and Miller–Rabin uses 127 bits; larger timeouts are not omitted from the
qualification results above.

FIR includes the diagnostic Node adapter, copied result, common text formatting
and cache-aware heap rewind. VIR includes SDK decoding and common formatting.
Native uses in-process function/Lean-formatting time, dropping the first of two
calls in each fresh process. Startup/compilation are excluded. FIR/VIR receive
one explicit warmup before the six measured calls. Native’s fresh-process
warmup policy differs, so interpret these as exploratory backend observations.

The small-integer/array-heavy workloads improve substantially relative to VIR.

identifies large-integer execution as a priority for sampled attribution.
The [subsequent fibBits profile](FIR-FIBBITS-PROFILE-20260928.md) identifies FIR's
generic repeated-doubling/addition multiplication path and its hot limb-access
helpers; it does not change these original comparison measurements.

versus native/VIR 4.34.0. No client build or other client benchmark ran alongside
the campaign; background load, affinity and governor were uncontrolled. Native
medians differ from the earlier original-harness run, so do not mix the two

The ordinary-interface Bench.tunnell package additionally passes all seven
